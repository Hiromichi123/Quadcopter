# DVS 悬停避障处理链设计与实验说明

## 1. 任务拆解

目标：在悬停无人机中，利用 DVS 的高时间分辨率快速识别篮球目标，并根据接近趋势触发规避动作。

处理链拆解如下：

1. 事件采集：串口读取 MCU 2 字节事件协议，解包为 `(x, y, p, dt_us)`。
2. 事件滤波：压制无效高频抖动、闪烁点，降低误检和算力浪费。
3. 目标识别：针对“球体”尝试多个识别策略并可切换。
4. 接近判断：利用事件能量增长判断目标是否正在逼近。
5. 动作生成：满足阈值后发布规避指令（`geometry_msgs/Twist`）。
6. ROS 发布：发布原始事件、滤波事件、识别状态和规避指令。

## 2. 已实现程序结构

主节点：`vision_py/scripts/dvs_raw_serial_node.py`

新增处理模块：`vision_py/scripts/dvs_event_processing.py`

其中：

1. `EventFilter`
- 像素不应期滤波（`refractory_us`）：抑制同像素短时间重复触发。
- 极性翻转滤波（`flicker_window_us`）：抑制极短时间内 `p` 翻转造成的闪烁噪声。

2. `BallDetector`
- `density`：网格密度峰值法，寻找热点区域。
- `cluster`：连通域法，依据最大簇大小、包围盒长宽比、填充率评估球形可能性。
- `radial`：径向一致性法，基于半径均值与变异系数评估圆形特征。

3. `compute_avoidance_command`
- 输入识别结果和阈值，输出 `(vx, vy, vz)`。
- 采用简单启发式：当置信度和接近分数均达标时，后退并向球体相反方向侧移。

## 3. 节点参数与话题

### 3.1 关键参数

- `processing_enabled`：是否启用处理链。
- `processing_strategy`：`density` / `cluster` / `radial`。
- `filter_refractory_us`：像素不应期。
- `filter_flicker_window_us`：极性闪烁抑制窗口。
- `filter_strength`：综合滤波强度（0~1），一键联动滤波与触发门限；小于 0 表示关闭联动，使用各子参数原值。
- `filter_min_component_pixels`：最小连通块像素阈值，小于该值的连通块会被剔除。
- `detect_min_events`：最小事件数门限。
- `avoid_confidence_threshold`：规避置信度阈值。
- `avoid_approach_threshold`：规避接近阈值。
- `visualize_enabled`：是否打开可视化窗口。
- `visualize_window_name`：窗口标题。
- `visualize_scale`：窗口放大倍数（基于 128x128）。
- `visualize_use_filtered`：窗口显示滤波后事件（`true`）或原始事件（`false`）。
- `visualize_compare_mode`：左右对比显示 raw 与 filtered（开启后优先于 `visualize_use_filtered`）。
- `visualize_circle_thickness`：结果圆圈线宽。
- `visualize_circle_expand_px`：结果圆半径附加扩展像素。
- `visualize_confidence_threshold`：仅当置信度达到该值才绘制“当前帧最可能圆”。

### 3.2 发布话题

- 原始事件：`/dvs/events`（`sensor_msgs/PointCloud2`）
- 滤波事件：`/dvs/events_filtered`（`sensor_msgs/PointCloud2`）
- 识别状态：`/dvs/ball_detection`（`std_msgs/String`，JSON 字符串）
- 规避指令：`/dvs/avoid_cmd`（`geometry_msgs/Twist`）

## 4. 多方案测试建议

建议固定采样场景并只改 `processing_strategy`，对比三种策略。

### 4.1 场景设置

1. 无人机悬停，背景尽量稳定。
2. 篮球在画面中心、左侧、右侧分别做接近动作。
3. 记录每次试验的识别率、误触发率、触发延迟。

## 5. 方案优缺点

1. density
- 优点：计算最轻，延迟低。
- 缺点：对背景局部高频扰动较敏感。

2. cluster
- 优点：可利用几何连通性抑制散点噪声。
- 缺点：在事件稀疏或目标边缘不连续时稳定性下降。

3. radial
- 优点：直接利用“球体/圆形”先验。
- 缺点：对遮挡、偏心和非完整轮廓较敏感。

## 6. 调参优先级建议

按以下顺序调参：

1. 快速整体调节时：先用 `filter_strength`（0=最弱，1=最强）。
2. 需要精细控制时：再单独调 `filter_refractory_us`、`filter_flicker_window_us`。
3. 再调连通块阈值：`filter_min_component_pixels`。
4. 再调识别门限：`detect_min_events`。
5. 最后调动作触发：`avoid_confidence_threshold`、`avoid_approach_threshold`。

推荐起步值：

1. 室内稳定光照：`filter_strength=0.35`
2. LED 干扰明显：`filter_strength=0.60`
3. 干扰非常强、宁可漏检：`filter_strength=0.80`
4. 仅保留剧烈变化：`filter_strength=1.00`

经验上，若误触发多，先提高 `detect_min_events` 和 `avoid_confidence_threshold`。
若触发太慢，适当降低 `avoid_approach_threshold`。

## 7. 当前实现边界与下一步

当前版本是“快速可试验”链路，适合离线调参和在线验证。

可视化窗口说明：

1. 绿色点表示 ON 极性事件，蓝色点表示 OFF 极性事件。
2. 红色圆圈为当前检测到的球体中心和近似半径。
3. 单窗模式：左上角叠加文本显示当前策略、原始/滤波事件数、规避状态。
4. 对比模式：左侧固定为 raw，右侧固定为 filtered+result，并分别显示事件数。
5. 窗口中按 `q` 或 `ESC` 可关闭可视化，不影响节点继续发布。

后续可升级方向：

1. 引入轻量时空体素表面（time-surface）增强接近估计。
2. 在识别状态中增加速度/方向估计并输出预测碰撞时间（TTC）。
3. 将 `std_msgs/String` 状态改成自定义消息，避免 JSON 解析。
4. 增加一个 strategy=ensemble，对三种策略做加权投票。
